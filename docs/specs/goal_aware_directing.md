# Context
Replay Highlights is a grassroots-football highlights app (FastAPI backend in `highlights/app/backend`, React/Vite frontend in `highlights/app/frontend`, multi-angle pipeline in `highlights/multiangle`). For multi-angle matches (3 fixed phone cameras around a small pitch) the pipeline syncs the angles (`sync.py`), extracts per-second ball/player features per angle (`trackfeat.py` -> `angles/a*/track/features_1s.json`), then `director.py` picks which camera to show each second and emits `multiangle/director.json` with `segments: [{angle, t_start, t_end, rule, score, ...}]` (times in "output time", 0 = start of the cut range), and `render.py` cuts the three source videos accordingly into `match.mp4`. `run.py` orchestrates stages (`director`, `render`, `fuse`, `stats`). Cuts are versioned under `multiangle/cuts/<id>/` (`cuts.py`). `manual_direct.py` / `learned_zones.py` implement a "You Direct" mode where the user manually directs stretches and the director learns style overrides from them (`director_params.json`). Confirmed match events (goals / shots / chances) live in `pipeline/candidates.json` (candidates with `type`, `t` in output time, `clip_start/clip_end`, `status` confirmed/rejected/pending, and `signals.team` = "home"/"away" for goals). Camera-to-pitch calibration: `multiangle/calib.json` / `calib_refined.json` (see `highlights/analysis/calib.py`, and `radar_pitch.json`), which maps each camera's image to pitch coordinates — you can derive which pitch end (goal) each camera faces / has closest.

Read `highlights/multiangle/director.py`, `run.py`, `render.py`, `cuts.py`, `manual_direct.py`, `learned_zones.py`, the tests in `highlights/multiangle/tests/`, and the backend endpoints in `highlights/app/backend/main.py` that mention `multiangle` before designing.

# Task: goal-aware directing + second-angle replay
Implement, as an optional director feature that applies to BOTH the automatic AI cut and the learned "You Direct" cut:

1. **Goal-aware camera hold.** Around every confirmed goal/shot/chance candidate (statuses `confirmed`; types in the shot family, see `SHOT_TYPES` in `highlights/analysis/stats.py`), from ~6 s before to ~4 s after the event time, the director must choose the camera that best sees the goal being attacked — determined from calibration (which camera's view contains / is nearest that pitch end, using the ball's pitch-x at the event to pick the end) with a fallback to the camera whose per-second features show the ball/players most in the attacking third — and hold it (no switching) across that window. Encode this as a director rule (e.g. `rule: "goal_hold"`) so it's visible in `director.json` and in the UI's segment hover.

2. **Second-angle slow-motion replay.** Immediately after the post-roll of each confirmed GOAL (type `goal` only), insert a replay: the ~6 s leading up to and including the goal, from a DIFFERENT camera than the one used for the live hold (prefer the second-best goal-facing camera), played at 0.5x speed (so ~12 s of output), with a small "REPLAY" text tag (ffmpeg drawtext, DejaVuSans font exists at /usr/share/fonts/truetype/dejavu/ on the server; degrade gracefully if drawtext/font missing). Then resume live action after the goal window. Replays therefore lengthen the output; every timestamp consumer (candidates `t`, stats, the UI's segment timeline, `manual_direct` stretch mapping) works in output time — you must add an explicit output-time mapping (e.g. `director.json` gets a `replays: [{src_angle, t_src_start, t_src_end, t_out_start, t_out_end, speed}]` list and a helper `to_output_time_with_replays(t)` / inverse) and update `stage_fuse` in `run.py` so candidate/event times in `pipeline/candidates.json` are shifted correctly past inserted replays. Keep it correct rather than clever; add tests for the mapping.

3. **Render support.** Extend `render.py` so segments can carry `speed` (0.5) and an overlay tag; the mezzanine/segment-cache design must still work (replay segments are extra segments with re-encode for the slow-motion via `setpts=2*PTS` and audio `atempo=0.5` or muted audio — your call, state it in the PR). Output stays 1920x1080 30 fps, same encode settings.

4. **Setting + UI.** Project-level toggle stored in the project meta (backend: `ProjectStore.meta`, e.g. `goal_aware: true` default ON for new re-cuts; expose via the existing multiangle info/settings endpoints) and a checkbox in `highlights/app/frontend/src/components/DirectorCut.tsx` ("Goal-aware: hold goal camera + slow-mo replay") so the user can disable it before a re-cut. Show replay segments distinctly on the segment timeline.
