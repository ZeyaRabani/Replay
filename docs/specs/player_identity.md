# Context
Replay Highlights is a grassroots-football highlights app (FastAPI backend in `highlights/app/backend`, React/Vite frontend in `highlights/app/frontend`, player analysis in `highlights/analysis`). For multi-angle matches (3 fixed phone cameras around a ~48x45 m pitch, ~22 players, ~63 min) the "players v2" run detects players per camera with YOLO (`detect_hr.py` -> `analysis/players_v2/det_a{0,1,2}.npz` + meta), projects them to pitch metres with the calibration (`calib.py`, `multiangle/calib*.json`), fuses them across cameras into pitch-space tracks (`fuse_tracks.py` -> `tracks.json`, each track: `start`, `xy` per 0.5 s STEP, `team` "A"/"B"/None from kit colour, distance/sprint stats, ~6 thumbnail crops per track in `crops/`), and clusters tracks into likely-same-player groups (`groups.py` / `groups_v2.py` -> `groups.json`, constraint: tracks overlapping in time >= 1 s cannot be the same person). Team identification (shirt colour A/B, names, hex) is in `teams.py` -> `analysis/teams.json`. The backend serves this via endpoints in `highlights/app/backend/main.py` (search "players_v2", "groups", "radar") and the frontend shows a Radar replay (`components/RadarReplay.tsx`) and player cards (`pages/ProjectStats.tsx`, `components/PlayerAnalysis.tsx`, `lib/players.ts`). The per-track stats (distance, sprints) are currently per fragment, not per person — that's the problem to fix.

Current 28/8 result (attached bundle, `analysis/players_v2/`): 1,249 fused tracks, mean track length ~60 s, median 19–22 players visible at once, 63 groups. Groups are still fragments, not 22 whole-match players.

# Task 1: whole-match player identity
Build `highlights/analysis/identity.py` that links the fused tracks into a small set of persistent player identities (target: ~11 per team, i.e. ~22 total, plus a spare bucket for referee/unassigned), using:
- kit colour / team label (never merge across teams),
- the cannot-link constraint (time overlap >= 1 s => different people; also two identities can't both be on the pitch at more than the team size, i.e. at any second each team has at most ~11 identities active),
- spatial-temporal continuity (a track that starts near where another ended a few seconds earlier is likely the same player; use a gap-cost = f(distance, gap time, plausible speed <= ~8 m/s)),
- appearance from the crops (cheap colour histogram / mean colour embedding per track from `crops/`; no deep re-ID models, CPU only, no new heavy deps beyond what's in `pyproject.toml` — numpy/opencv/scikit-learn if already present),
- optionally the players' role prior (goalkeepers stay near their goal).
Formulate it as a constrained assignment (e.g. greedy/Hungarian linking on a gap-cost matrix with team-size caps, or min-cost flow if networkx is already available) — explain the choice in the PR. Output `analysis/players_v2/identities.json`: `{identities: [{id, team, track_ids, first_s, last_s, coverage_s, distance_m, sprints, top_speed_ms, crops: [..up to 6 representative..], name: null}], unassigned_track_ids: [...], quality: {...}}` where per-identity stats are aggregated from the member tracks. Provide a CLI (`python -m highlights.analysis.identity <players_v2_dir>`) and wire it into the players run (`players_run.py`) so it runs automatically after grouping; also make it re-runnable offline from the saved tracks (no re-detection).

Honest evaluation on the real 28/8 data (attached): report number of identities per team, coverage (% of match seconds each identity is tracked), how many tracks stayed unassigned, and total distance per identity (sanity: an outfield player over ~60 min should be ~4–7 km; a goalkeeper less).
